## How this list is produced, and what it cannot see

Generated offline from the repository — no part of it is hand-maintained, so it cannot
drift out of step with the code the way a hand-written list does.

- **Part 1** compares `lang/en.json` against `tools/i18n/baseline/es.json`, which
  records the English each of your translations was verified against and advances
  automatically whenever you import a returned spreadsheet.
- **Part 2** compares `lang/content/es.json` against every English string the
  packs actually offer, using the same classification `npm run i18n:check` gates on.

**The one gap worth knowing about:** the Part 1 baseline was seeded at `0.1.16`, so it
cannot see an English string that changed *before* then. It is a floor from which drift
is caught going forward, not a full history.

205 translated key(s) have no baseline entry at all — translated after the
seed and not yet re-imported, so nothing is known about the English behind them. They
are neither reported as drifted nor certified as current.
